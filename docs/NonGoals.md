# NonGoals.md — AI Christmas Tree Decorator

ต่างจาก "Out of Scope" ใน Product.md (ซึ่งคือ "ยังไม่ทำ เดี๋ยวทำทีหลัง")
ไฟล์นี้คือ **ห้ามทำแม้ Builder จะคิดว่ามันดี/ง่าย/เพิ่มมูลค่าระหว่างเขียนโค้ด**
เป้าหมาย: กัน scope creep ที่มักเกิดจากความตั้งใจดี ไม่ใช่ความประมาท

## ห้ามทำเด็ดขาดใน MVP

1. **ห้ามเพิ่ม feature ที่ Product.md ไม่ได้ระบุ** แม้จะดู "ใกล้เคียง" เช่น:
   - ~~ห้ามเพิ่ม auto-crop/auto-suggest ต้นไม้ที่เหมาะกับ element (นั่นคือ recommendation engine — คนละงานกับ compositing tool)~~
     **← ยกเลิกบางส่วน 2026-08-05**: recommendation engine เข้า scope แล้วใน Product.md ข้อ 8.3
     (ดูรูป ref แล้วแนะรหัสสินค้า + ปริมาณ) — แต่**เข้าเฉพาะรูปแบบที่ Product.md 8.3 กำหนดไว้เท่านั้น**
     คือ top-3 พร้อมคะแนน และปฏิเสธเมื่อคะแนนต่ำ. **ยังห้าม** ตอบรหัสเดียวแบบมั่นใจ
     และยังห้าม auto-suggest ที่ผู้ใช้ไม่ได้ขอ (เช่น เด้งขึ้นมาเองตอนอัปโหลด)
   - ห้ามเพิ่มระบบ gallery/social share ในตัว (ไม่ใช่เป้าหมาย — เป้าหมายคือเครื่องมือสร้างภาพ ไม่ใช่ platform)

2. **ห้ามเปลี่ยน engine กลับไป/มาระหว่าง implement** — gpt-image-2 ตัดสินใจแล้วใน Product.md ถ้าเจอปัญหาระหว่างทาง (เช่น ราคาแพง, quality ไม่พอ) ต้องยกกลับ Architect ทบทวน ไม่ใช่ Builder เปลี่ยนเอง

3. **ห้ามข้าม background-removal step** แม้จะพบว่า "ส่งรูปดิบเข้า gpt-image-2 ตรง ๆ ก็ได้ผลลัพธ์โอเคในบางเคส" — ตัดสินใจนี้ต้องยกกลับ Architect เพราะกระทบความสม่ำเสมอของคุณภาพทั้งระบบ ไม่ใช่แค่เคสเดียว

4. **ห้ามเรียก API ที่เสียเงินก่อน user กด confirm และห้ามเรียกซ้ำสำหรับ request เดียวกัน** (ผูกกับ AC-4) — แม้จะ "ง่ายกว่า" ถ้ายิงตอน request เข้ามาเลย
   *ปรับ 2026-08-05: เดิมเขียนว่า "ห้ามหัก credit ก่อนยืนยันว่าสำเร็จ" — ระบบ credit ถูกยกเลิกแล้ว (Product.md ข้อ 6) แต่ข้อห้ามยังอยู่ในรูปที่ตรงกว่าเดิม เพราะเงินออกจริงตอนเรียก API ไม่ใช่ตอนหัก counter*
   - ห้ามเพิ่ม balance/credit/wallet ท้องถิ่นกลับเข้ามาโดยไม่ผ่าน Architect — OpenAI ไม่เปิด endpoint ให้อ่านยอดคงเหลือ ตัวเลขแบบนั้นจึงกรอกมือและเพี้ยนได้เสมอ
   - ห้ามใส่ auto-retry ตอน generation fail — ทุก retry คือเงินอีกก้อน ต้องให้ user กดเอง

5. ~~**ห้ามทำ multi-element ผสมเข้ามาระหว่างทาง**~~ **← ยกเลิก 2026-08-05**: multi-element (1–5 ชิ้น)
   เข้า V1.1 แล้วตาม Product.md ข้อ 8.2

   **เหตุผลเดิมยังใช้ได้และกลายเป็นเงื่อนไขแทน**: การผสม multi-element จะทำให้ prompt baseline
   ของ single-element เสียหลักฐานเปรียบเทียบ ดังนั้น —
   - **ต้องปิด AC-5 ของ single-element ให้จบก่อน** จึงเริ่ม multi-element ได้
   - multi-element ต้องมี AC ของตัวเอง ห้ามเอาเลข ≥70% ของ single-element มาอ้างแทน

6. **ห้ามลด/ข้าม input validation** (ประเภทไฟล์, ขนาด) แม้ demo ภายในจะไม่จำเป็น — เพราะ production จริงต้องมีตั้งแต่ AC-1 ไม่ใช่แพตช์เพิ่มทีหลัง

## ห้ามเด็ดขาดใน V1.1 (เพิ่ม 2026-08-05)

7. **ห้ามตอบรหัสสินค้าแบบมั่นใจตัวเดียว** — ต้องเป็น top-3 พร้อมคะแนนเสมอ และต้องปฏิเสธได้
   เมื่อคะแนนต่ำกว่า threshold. รหัสผิด = ลูกค้าสั่งของผิด = ความเสียหายจริงที่ตกกับร้าน
   ไม่ใช่ bug ที่แก้แล้วจบ
8. **ห้ามเดาขนาดสินค้า** — ขนาดต้องมาจากข้อมูล catalogue (Product.md 8.1) เท่านั้น
   ถ้าชิ้นไหนไม่มีข้อมูลขนาด ต้องบอกว่าไม่มี ห้ามประมาณจากรูป
9. **ห้ามทำ 3D rendering / physics simulation** เพื่อไล่ตาม "แสงเงาเป๊ะ" — ยังอยู่ Out of Scope
   ความเป๊ะมาจากตัวเลขขนาดจริงที่ป้อนเข้า prompt ถ้าเท่านี้ยังไม่พอ ต้องยกกลับ Architect

   **อัปเดต 2026-08-05**: วัดแล้ว prompt ทำให้ขนาด**สม่ำเสมอ**ได้ (spread 1.86 → 1.12 เท่า)
   แต่ทำให้**ถูกต้องสัมบูรณ์**ไม่ได้ (ยัง 0.55–0.70 ของจริง) และการชดเชยด้วยตัวคูณ
   ทำให้แย่ลง ไม่ใช่ดีขึ้น → ถ้าจะเอาความถูกต้องสัมบูรณ์ ต้องยกกลับ Architect ตามข้อนี้

10. **ห้ามส่งค่า API key กลับมาแสดงในหน้าเว็บ** (ผูกกับ Product.md 8.4) — ช่องกรอกเป็น write-only
    แสดงได้แค่ "ตั้งค่าแล้ว / ยังไม่ได้ตั้ง" · ห้ามเก็บลง SQLite · ห้ามโผล่ใน log หรือ error
    · ถ้า bind นอก localhost ต้องมี auth **ก่อน** เปิดช่องนี้ ไม่ใช่หลัง

## เมื่อเจอสถานการณ์ที่อยากทำสิ่งเหล่านี้
