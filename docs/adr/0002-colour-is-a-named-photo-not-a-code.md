# A colour is a named photo of a code, not a code of its own

These catalogues photograph a product across its whole colour range in one frame — one code, six
colours, one picture — so the app splits that frame and offers one card per colour. The question
was whether a colour should become its own identifier (`4400-1/RED`) or stay an attribute of the
one code. It stays an attribute: the books sell these as a single code, and minting sub-codes would
put identifiers into the generation history and the staff worksheet that no supplier could be
ordered from. Instead each split photo carries a Thai colour name, and that name rides alongside
the code wherever a person is going to order from it.

## Consequences

- A main photo is chosen per colour, not per code — picking "red" and generating from the green
  photo would otherwise be the normal case for any split product.
- Colour reaches the generation history and the staff worksheet, but not the count-what's-in-the-
  picture feature, which reads a finished image and has no catalogue knowledge to bring colour in.
- If a shop ever genuinely orders one colour separately from another, this is the decision to
  revisit — that would make the colour a product, not an attribute.
